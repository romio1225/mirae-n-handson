# 문항 은행(item-bank) 비즈니스 규칙 후보 — 문항 검색 화면

> 분석 대상: `legacy/item-bank-php` · 범위: 문항 검색 화면(`GET /search.php`)과 그 화면이 부르는 코드 · 선행 문서: `docs/item-bank/ARCHITECTURE.md`, `docs/item-bank/ERD.md` · 근거 경로는 저장소 맨 위 기준
>
> 특히 본 곳: 공개 여부, 난이도 조건, 입력값 보정(자르기 · 형식), 정렬 기본값, 페이지 경계, 0건 처리
>
> 약칭: `S` = `legacy/item-bank-php/search.php`, `SCH` = `db/mariadb/init/01-schema.sql`. 근거 칸에는 전체 경로를 적는다.

## 1. 조회 대상

### BR-01
- 규칙: 검색은 상태가 `'A'`(공개)인 문항만 대상으로 한다. `D`(삭제) · `R`(검수중)은 나오지 않는다.
- 근거: `db/mariadb/init/01-schema.sql:70`, `legacy/item-bank-php/search.php:522`
- 근거 코드 (`SCH:70`, 뷰 `v_item_public` 의 조건):
    ```sql
    WHERE i.status = 'A';
    ```
- 확신도: 확실
- 비고: 검색 화면은 이 뷰에서만 읽는다(`S:522`). 상태값의 뜻은 주석에만 있다(`SCH:26`).

### BR-02
- 규칙: 난이도(`level`)가 비었거나 없으면 **난이도 5 를 뺀** `level < 5` 조건이 붙는다. 즉 기본 검색에는 난이도 5 문항이 나오지 않는다.
- 근거: `legacy/item-bank-php/search.php:211-216`
- 근거 코드:
    ```php
        if ($level == '') {
            $where .= " AND level < 5";
    ```
- 확신도: 확실
- 비고: **주석과 코드가 다르다.** 주석은 "난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)"(`S:213`), 머리 주석도 "빈값 허용"(`S:8`). 코드는 `< 5`. 파라미터가 아예 없을 때도 `$level = ''` 로 시작하므로 같은 경로다(`S:61`). 동작 보존 테스트의 핵심 경계.

### BR-03
- 규칙: 난이도가 정확히 한 글자 `1`~`5` 이면 그 난이도와 같은 문항만 찾는다.
- 근거: `legacy/item-bank-php/search.php:217-221`
- 근거 코드:
    ```php
        else if (preg_match('/^[1-5]$/', $level)) {
            $where .= " AND level = ?";
    ```
- 확신도: 확실
- 비고: 앞뒤 공백은 먼저 지운다(`S:211`).

### BR-04
- 규칙: 난이도가 그 밖의 값이면 "난이도는 1~5 사이여야 합니다." 경고를 띄우고, **정수로 바꾼 값**으로 그대로 조회한다.
- 근거: `legacy/item-bank-php/search.php:223-229`
- 근거 코드:
    ```php
            $warnings[] = '난이도는 1~5 사이여야 합니다.';
            $values[] = (int)$level;
    ```
- 확신도: 확실(코드) / 결과 값은 PHP `(int)` 변환 규칙에 따른 추정
- 비고: `0` · `6` · `-1` · `abc`(→0) 는 대개 0건이다. 그러나 `05` · `3.5` 처럼 정규식은 틀려도 정수 변환이 1~5 가 되는 값은 **경고와 함께 결과가 나온다**(`05`→5, `3.5`→3). 이 경로는 난이도 5 도 찾을 수 있다.

## 2. 키워드 · 단원 · 태그

### BR-05
- 규칙: 키워드(`q`)는 앞뒤 공백을 지우고, 100자를 넘으면 100자로 자르고 경고한다.
- 근거: `legacy/item-bank-php/search.php:85-89`
- 근거 코드:
    ```php
        if (mb_strlen($q, 'UTF-8') > 100) {
            $warnings[] = '키워드가 너무 길어 100자까지만 사용했습니다.';
    ```
- 확신도: 확실
- 비고: 정확히 100자는 자르지 않는다(`>`). 폼 입력칸도 `maxlength="100"` (`S:494`). 아주 긴 값(1000자 한글)은 이 코드에 닿기 전에 웹 서버가 HTTP 414 로 거절한다(베이스라인에서 확인).

### BR-06
- 규칙: 키워드는 제목 **또는** 지문에 포함되면 찾는다(`LIKE '%키워드%'`). `%` · `_` 는 이스케이프하지 않고 와일드카드로 쓰며 경고만 띄운다.
- 근거: `legacy/item-bank-php/search.php:94-98`
- 근거 코드:
    ```php
            $like = '%' . $q . '%';
            $where .= " AND (title LIKE ? OR stem LIKE ?)";
    ```
- 확신도: 확실
- 비고: 한 글자 키워드는 "결과가 많을 수 있습니다" 경고만 띄우고 그대로 찾는다(`S:91-92`). 대소문자 구분은 collation `utf8mb4_unicode_ci` 를 따른다(`SCH:33`).

### BR-07
- 규칙: 단원(`unit`)은 단원 코드와 같음(`=`)으로 찾는다. 형식(`M5-1` 꼴)이 틀리거나 소문자가 섞이면 경고하지만 **입력값 그대로 조회한다**.
- 근거: `legacy/item-bank-php/search.php:109-120`
- 근거 코드:
    ```php
            if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
            if ($unit !== strtoupper($unit)) {
            $where .= " AND unit_code = ?";
    ```
- 확신도: 확실(코드) / 소문자 입력의 결과는 추정
- 비고: collation 이 대소문자를 무시하므로(`SCH:18`) `m5-1` 은 경고("대문자로 입력하세요")가 뜨면서도 `M5-1` 결과가 나올 것으로 보인다 — 실행으로 확인 필요.

### BR-08
- 규칙: `unit` 테이블에 없는 단원 코드면 "등록되지 않은 단원 코드입니다: …" 경고를 띄우고, 조회는 그대로 한다(결과 0건).
- 근거: `legacy/item-bank-php/search.php:123-146`
- 근거 코드:
    ```php
                $warnings[] = '등록되지 않은 단원 코드입니다: ' . $unit;
    ```
- 확신도: 확실

### BR-09
- 규칙: 태그(`tag`)는 태그 이름과 같은(`=`) 태그가 붙은 문항만 찾는다. 50자를 넘으면 50자로 자르고 경고한다. `%` · `_` 가 있으면 "부분 일치를 지원하지 않습니다" 경고만 띄운다.
- 근거: `legacy/item-bank-php/search.php:235-247`
- 근거 코드:
    ```php
            if (mb_strlen($tag, 'UTF-8') > 50) {
                    . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
    ```
- 확신도: 확실
- 비고: 태그 이름 컬럼도 50자다(`SCH:37`).

### BR-10
- 규칙: 입력한 태그가 태그 목록에 없으면 "등록되지 않은 태그입니다: …" 경고를 띄운다. 목록 비교는 PHP `===`(대소문자 구분)다.
- 근거: `legacy/item-bank-php/search.php:251-260`
- 근거 코드:
    ```php
                if ($opt['value'] !== '' && $opt['value'] === $tag) {
    ```
- 확신도: 확실(코드) / 대소문자 차이 결과는 추정
- 비고: SQL 비교는 대소문자를 무시하므로(`SCH:40`), 대소문자만 다른 태그는 "등록되지 않은 태그" 경고와 결과가 **함께** 나올 수 있다.

## 3. 정렬

### BR-11
- 규칙: 정렬 기준이 없으면 난이도 내림차순, 같으면 id 오름차순이다. 모르는 기준이면 경고하고 같은 기본 정렬을 쓴다.
- 근거: `legacy/item-bank-php/search.php:317-326`
- 근거 코드 (`S:319`):
    ```php

    ```
- 확신도: 확실
- 비고: 정렬 기준은 대소문자를 무시한다(`strtolower`, `S:266`).

### BR-12
- 규칙: 정렬 기준별 방향 기본값과 보조 정렬이 다르다. `id` · `title` · `unit` 은 기본 오름차순, `level` · `created` 는 기본 내림차순이다. `unit` 정렬은 방향과 상관없이 보조 정렬이 `level DESC, id ASC` 다.
- 근거: `legacy/item-bank-php/search.php:276-316`
- 근거 코드:
    ```php
                    $orderBy = " ORDER BY unit_code ASC, level DESC, id ASC";
                if ($dir === 'asc') {
    ```
- 확신도: 확실
- 비고: `level` · `created` 는 `dir === 'asc'` 일 때만 오름차순이고 나머지는 모두 내림차순이다(`S:302`, `:310`).

### BR-13
- 규칙: 정렬 방향(`dir`)이 `asc` · `desc` 가 아니면(빈값 제외) 경고하고 방향을 무시한다.
- 근거: `legacy/item-bank-php/search.php:267-273`

- 근거: `legacy/item-bank-php/search.php:336-349`, `:523`
