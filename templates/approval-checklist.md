# 승인 체크리스트 v1

v1 · 2회차 (2026-10-06, 에듀테크R&D팀 초안)

오늘 바뀐 점
- "충분한가 · 적절한가 · 심각한가 · 지나치게" 같은 판단 문구를 없애고 모든 항목을 예/아니오 문장으로 바꿨다.
- 반려 조건을 기준마다 [반려] · [경고] 표시로 못 박았다. 치명에 저장소 금지 사항을 넣었고, 새 테스트 누락 · 네이밍은 경고로 내렸다.
- 테스트 명령 · 검증 범위 · 근거 줄번호 대조 · "확인 필요" 처리를 이 저장소 기준으로 정했다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 각 항목에 "예 / 아니오 / 확인 필요"로 답한다.
**[반려]** 항목이 하나라도 "아니오"면 반려다. **[경고]** 항목의 "아니오"는 이슈 목록에 경고로 남기고 판정에는 영향을 주지 않는다.

## 심각도 정의

- **치명** — 2장(치명 이슈 0건)의 [반려] 항목에 걸리는 문제에만 쓴다. 1건이라도 있으면 반려.
- **경고** — 1 · 3 · 4장의 [반려] 항목에 걸리는 문제(그 기준을 미충족으로 표시하고 판정은 반려), 그리고 [경고] 항목에 걸리는 문제(판정에 영향 없음). 1 · 3 · 4장 위반을 치명으로 올리거나 "치명 이슈 0건" 기준을 미충족으로 만들지 않는다.
- **제안** — 체크리스트 항목에 걸리지 않는 개선 의견. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 0. 판정 전 확인

- [ ] [반려] 요청 문장이 한 문장으로 주어졌다(없으면 판정하지 않고 먼저 묻는다).
- [ ] [반려] 검증 범위(git 범위 또는 patch)가 요청 1건에 해당하는 커밋만 담고 있다(여러 요청이 섞였으면 범위를 좁혀 달라고 묻는다).
- [ ] [반려] 이슈 표의 모든 `파일:줄번호` 를 사람이 원본 파일과 대조해 일치를 확인했다(어긋난 행은 고치고 "(사람 판정)" 표시).

## 1. 테스트 통과

- [ ] [반려] 바뀐 폴더의 검증 명령을 실제로 실행했다 — `modern/api`: `./gradlew test` / `modern/web`: `npm run lint && npm run typecheck && npm test` / 이관 코드: `characterization` 에서 `npm test` 와 `TARGET_BASE_URL=http://localhost:8080 npm test`.
- [ ] [반려] 실행한 명령의 실패 · 오류 수가 0이다(아직 이관하지 않은 모듈의 characterization 실패는 모듈 이름과 함께 따로 적고 0으로 센다).
- [ ] [반려] 기존 테스트를 지우거나 `@Disabled` · `.skip` · `.only` 로 바꾼 줄이 없다.
- [ ] [경고] 새 public 서비스 메서드 · 새 엔드포인트 · `src/components/` 의 새 컴포넌트마다 그것을 호출하는 테스트가 1개 이상 있다(getter · setter · 생성자 · record 접근자는 제외).

## 2. 치명 이슈 0건

- [ ] [반려] 비밀번호 · 토큰 · 키 리터럴이 코드 · 설정 · 테스트 픽스처에 없다(실습용 더미 `app-pass` 와 `db/` 시드 · `docker-compose.yml` 의 로컬 계정은 제외).
- [ ] [반려] SQL 을 문자열 이어 붙이기로 만드는 줄이 없다(모든 값은 파라미터 바인딩).
- [ ] [반려] `DROP` · `TRUNCATE` 가 없고, 데이터를 지우거나 덮어쓰는 코드가 새로 생겼다면 요청 문장에 그 동작이 적혀 있다.
- [ ] [반려] 인증 · 권한 검사를 건너뛰거나 없애는 줄이 없다.
- [ ] [반려] `legacy/` 아래 파일이 바뀌지 않았다.
- [ ] [반려] `characterization/` 의 기존 테스트 줄 · 기존 스냅샷 항목이 수정되거나 삭제되지 않았다(새 케이스 · 새 스냅샷 항목 추가만 허용).
- [ ] [반려] 로그 메시지 인자에 학생 식별자(`STU-…`) · 이메일 · 토큰 값이 들어가지 않는다.
- [ ] [반려] 운영 DB 호스트 주소나 `.env` 파일을 만들거나 읽는 코드 · 설정이 없다.

## 3. 요청 범위 이탈 없음

- [ ] [반려] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다(요청 문장에 없는 도메인 · 폴더의 파일이 1개라도 있으면 "아니오").
- [ ] [반려] 요청 파일 안에서도 요청과 무관한 줄 변경이 없다(같은 파일 안의 import 정리만 허용, 리팩토링 · 로그 문구 변경은 불허).
- [ ] [반려] `build.gradle` 의 `dependencies` · `package.json` · `package-lock.json` · `db/` 스키마 · 시드 · `application.yml` 접속 · 풀 설정이 바뀌었다면 요청 문장이나 PR 설명에 사람 승인이 적혀 있다.

## 4. 컨벤션 준수

`CLAUDE.md` 의 코딩 컨벤션 · 금지 사항과 `.claude/skills/convention-check/SKILL.md` 항목 1~8 로 대조한다. `CLAUDE.md` 에 예외가 적혀 있고 코드 주석에 사유가 있으면 "예"로 본다.

- [ ] [반려] 컨트롤러 생성자가 `*Service` 타입만 받고, 컨트롤러에 SQL 문자열 · `try`/`catch` 가 없다.
- [ ] [반려] 서비스가 다른 도메인의 `*Repository` 를 주입받지 않는다.
- [ ] [반려] 컨트롤러 반환 타입이 record 또는 그 `List` 다(`@Entity` 반환 없음).
- [ ] [반려] 빈 `catch` 블록이 없다(모든 catch 가 로그 후 다시 던지거나 감싸 던진다).
- [ ] [반려] `System.out` · `System.err` · `printStackTrace()` · `console.log` 가 없다.
- [ ] [반려] `src/main` 에 `@Autowired` 가 없고 `*Service` 에 인자 없는 `now()` 호출이 없다.
- [ ] [반려] 예외 → HTTP 상태 변환이 `GlobalExceptionHandler` 밖에 없다.
- [ ] [반려] `modern/web` 에서 `fetch` 호출이 `src/api/client.ts` 밖에 없고, 컴포넌트가 `src/api/` 를 직접 import 하지 않는다.
- [ ] [경고] 매직 넘버 대신 이름 붙인 상수를 쓰고 와일드카드 import 가 없다.
- [ ] [경고] 네이밍 규칙(핸들러 `handle<동작>` · 이벤트 prop `on<동작>` · 테스트 camelCase + 한국어 `@DisplayName`)을 지킨다.
- [ ] [경고] `any` · `@ts-ignore` · 사유 없는 `eslint-disable` · `getByTestId`(사유 주석 없이) · `toMatchSnapshot`(modern/web) 이 없다.
- [ ] [경고] 입력 값 범위 검증(예: 난이도 1~5)이 요청된 파라미터에 있고 범위 밖이면 400 을 돌려준다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향), 확인 필요 표.
- 기준 안에 "확인 필요"가 남아 있으면 그 기준은 "충족"으로 쓰지 않고 "확인 필요"로 쓴다. 이 경우 판정은 `반려(확인 필요)` 이며, 사람이 답하면 다시 판정한다.
- 코드는 수정하지 않는다.
