# 배치 · 적재 점검

- 로그 폴더: `$ARGUMENTS` (비어 있으면 `pipeline-samples/batch-logs`)
- 건수 표: 로그 폴더 옆의 `datamart-counts.csv` (기본 `pipeline-samples/datamart-counts.csv`)
- 날짜는 로그 줄의 `date=` 값(배치 기준일)으로 센다. 실행 시각은 다음 날 새벽이다.

## 점검 기준

| 점검 | 이상으로 보는 조건 | 근거로 남길 것 |
|---|---|---|
| 1. 실행 여부 | 다른 날에는 매일 돌던 job 이 그날 로그에 없거나, `status=START` 만 있고 `status=SUCCESS` 가 없음 | 로그 파일:줄번호(START 줄과 그 job 의 마지막 줄), CSV 에 그날 행이 있는지 |
| 2. 중복 실행 | 같은 날 같은 job 의 `status=SUCCESS` 가 2번 이상 | 두 실행의 START 줄번호 · 시작 시각 · run_id |
| 3. 적재 건수 | 같은 job 의 직전 7일(앞쪽 날짜는 있는 만큼) 평균에서 ±30% 를 넘음. 0건은 무조건 이상. 직전 날짜가 없으면 "비교 기준 없음" | CSV 줄번호 · 값 · 평균값 · 편차(%) |
| 4. 지연 | 소요 시간이 그 job 의 평소 소요 시간(전체 기간 `elapsed` 중앙값)의 2배를 넘음. `elapsed` 가 없으면 START · SUCCESS 시각 차로 계산 | SUCCESS 줄번호 · 시작 · 종료 시각 · 소요 · 평소 값 · 배수 |

## 규칙

- 이상마다 근거를 붙인다. 로그는 `파일:줄번호`, 건수는 `datamart-counts.csv:줄번호`(머리글이 1행).
- 로그를 통째로 읽지 않는다. `grep -n` · `awk` · `wc` 로 필요한 줄만 뽑는다. 단 `WARN` · `ERROR` 줄은 `status=RUNNING` 이어도 전부 뽑아 근거 후보로 본다.
- 평균 · 편차 · 중앙값 · 소요 시간은 암산하지 않고 `awk` 같은 명령으로 계산한다.
- 표에 넣기 전에 근거 줄번호를 `grep -n` 으로 다시 열어 내용이 맞는지 확인한다.
- 로그에 없는 원인은 추측하지 않는다. 원인 칸은 "확인 필요"로 두고 무엇을 더 봐야 하는지만 적는다. 로그에 적힌 사실(재실행 요청, lock 무시, SLA 경고 등)은 줄번호와 함께 그대로 옮긴다.
- 로그의 학생 식별자(`STU-…`) · 이메일 · 토큰 값은 리포트에 옮기지 않는다.
- 기준 4개 밖에서 눈에 띈 것은 리포트 표에 넣지 않고 답변 끝에 "기준 밖 관찰"로 한 줄씩만 적는다.
- 파일은 리포트 하나만 쓴다. 로그 · CSV · 다른 파일은 고치지 않는다.

## 출력

이상이 1건 이상이면 `docs/batch-check/report.md` 에 저장한다(있으면 덮어쓴다).

1. 맨 위 요약 한 줄: 점검 기간, 이상 건수(종류별)
2. 이상 목록 표: 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항
3. 맨 아래 "이상 없음으로 판정한 날짜" 목록

이상이 한 건도 없으면 파일을 만들지 않고 "이상 없음" 한 줄만 답한다.
