# RCA 리포트 마스킹 규칙

리포트(`docs/rca/*.md`)를 저장하기 전에 아래 규칙을 적용한다. 원본 로그는 고치지 않고, 리포트에 옮기는 발췌에만 적용한다.

| 유형 | 예시(원본 모양) | 바꾸는 값 |
|---|---|---|
| IP 주소 | `10.20.31.7` | 앞 두 자리만 남김 → `10.20.x.x` |
| IP 주소(구분 필요) | 로그에 서로 다른 IP 가 2개 이상 있고, 어느 IP 인지가 타임라인 · 가설에 쓰일 때(응답 서버 vs 거부 서버, 반복 요청한 단말). IP 가 1개뿐이거나 구분이 판단에 쓰이지 않으면 위 행(`10.20.x.x`) | 역할 별칭 → `API-1`, `API-2`, `DB-1`, `교사단말A`, `학생단말A` |
| 이메일 | `teacher01@school.example` | 역할 별칭 → `교사A`, `교사B` (구분 불필요하면 `<email>`) |
| 학생 식별자 | `STU-10234` | `학생A`, `학생B` (구분 불필요하면 `STU-xxxx`) |
| 토큰 · 세션 키 · API 키 | `Bearer eyJ…`, `token=…`, `api_key=…` | 키 이름만 남김 → `Bearer <token>`, `token=<masked>` |
| 비밀번호 · 접속 문자열 | `password=…`, `jdbc:…;password=…` | `password=<masked>`, 접속 문자열은 호스트 · 계정까지 가림 |

- 같은 원본 값은 리포트 전체에서 같은 별칭을 쓴다. 별칭은 등장 순서대로 A, B, C… 로 붙인다.
- 별칭 ↔ 원본 대응표는 파일로 남기지 않는다(대화 안에서만 유지).
- 인증 값이 아닌 식별자(DB `session_id`, 요청 경로, 학급 ID `C2` 등)는 남긴다.
- 리포트 끝에 유형별 마스킹 건수를 한 줄로 남긴다(예: `마스킹 적용: IP 1건 · 이메일 0건 · 학생 식별자 7건 · 토큰 0건 · 비밀번호 0건`).

## 확인용 패턴

저장 뒤 아래 패턴으로 리포트를 검사해 0건이어야 한다.

```bash
P='([0-9]{1,3}\.){3}[0-9]{1,3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|STU-[0-9]+|Bearer [A-Za-z0-9._-]{8,}|eyJ[A-Za-z0-9_-]{8,}|(token|api_key|password|pwd)=[^<[:space:]]+'
grep -nE "$P" docs/rca/<시나리오>.md
```
