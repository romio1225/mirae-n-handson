# 레거시 모듈 문서화

분석 대상: $ARGUMENTS

- 첫 단어는 모듈 경로, 나머지는 범위 제한이다. <모듈명>은 폴더 이름이 아니라 아래 셋 중 하나로 바꾼다.
  `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`
- 분석 대상 폴더의 파일은 읽기만 한다. 수정 · 기동 · 빌드하지 않는다(정적 분석).
- 모듈 밖에서는 그 모듈이 쓰는 테이블 정의(`db/<DB>/init/*schema*.sql`)와 `docker-compose.yml` 의 해당 서비스만 읽는다.
- 근거 경로는 저장소 맨 위 기준 `파일:줄번호` 로 적는다. 코드로 확인하지 못한 것은 추측하지 않고 "미확인"에 적는다.

## 절차

1. **계획 먼저.** 읽을 파일 목록 · 범위 · 산출물 3개를 보여 주고 승인을 받는다. 승인 전에는 파일을 열지 않는다.
   - 인자에 범위 제한이 있으면 그 범위 밖의 파일은 읽지 않는다. 범위 밖 호출은 "범위 밖"으로 표시만 한다.
   - 범위가 "화면 하나"처럼 고르는 말이면 고른 대상과 이유를 ARCHITECTURE.md 첫 절에 적고, 세 문서 머리말에 범위를 적는다.
   - gradle wrapper · vendor · node_modules 같은 외부 라이브러리 폴더는 제외한다.
2. **진입점 · 의존 관계** → `docs/<모듈명>/ARCHITECTURE.md` 저장.
   - 절: 모듈 개요 / 폴더 구조 / 진입점 표(URL·화면 | 처음 실행되는 파일·메서드 | 그 메서드가 부르는 주요 함수) / 의존 관계(mermaid + "A → B | 근거" 호출 표) / 가장 긴 함수 3개 / 미확인 목록
3. **데이터 흐름** → `docs/<모듈명>/ERD.md` 저장.
   - 절: 테이블 목록 / 테이블 관계(mermaid erDiagram, 관계마다 **선언 FK · 추정** 구분과 근거) / 데이터 흐름 / 읽기 · 쓰기 위치 표(테이블 | 읽는 함수:줄 | 쓰는 함수:줄) / 미확인
4. **비즈니스 규칙 후보** → `docs/<모듈명>/BUSINESS-RULES.md` 저장.
   - 제외 조건 · 반올림과 자릿수 · 누락 처리 · 상태값 · 날짜 비교 · 매직 넘버를 중심으로 본다.
   - 규칙마다 아래 형식을 그대로 쓴다. 뒤에 매직 넘버 표 / 같은 규칙이 두 곳에 다르게 있는 곳 / 주석만 있는 것 / 검증 이력(빈 표) 절을 둔다.
5. **인용 대조.** 저장 뒤 모든 근거 코드 줄을 원본 파일과 `grep -F` 로 대조하고, 없는 줄은 고친다.
6. **표본 점검 추천.** 사람이 직접 열어 볼 규칙 3개를 추천한다. 그중 하나는 가장 그럴듯하고 깔끔해 보이는 규칙이다. 각각 확인할 `sed -n '시작,끝p' 파일` 명령을 붙인다.
   - 사람의 판정은 BUSINESS-RULES.md "검증 이력" 표(날짜 | 규칙 | 뽑은 기준 | 판정 | 조치)에 남긴다.

단계가 끝날 때마다 파일을 먼저 저장하고, 무엇을 저장했는지 한 줄로 알린 뒤 다음 단계로 넘어간다.

## 규칙 형식

```
### BR-01
- 규칙: (한 문장. 조건과 결과)
- 근거: `legacy/.../파일:줄번호`
- 근거 코드:
    ```(언어)
    (원본 줄을 줄 전체 그대로)
    ```
- 확신도: 확실 | 추정 | 낮음
- 비고: (매직 넘버, 주석과의 차이, 다른 곳의 같은 규칙)
```

## 하지 말 것 (실제로 틀렸던 유형)

- 인용 코드를 줄 중간에서 자르지 않는다. 줄 전체를 옮기고 5단계에서 원본과 대조한다.
- 같은 조건이 두 파일에 있을 때 한쪽만 인용하고 다른 쪽을 같은 줄처럼 적지 않는다. 어느 파일 몇 줄을 인용했는지, 다른 쪽 표기가 어떻게 다른지 적는다.
- 주석만 보고 규칙을 쓰지 않는다. 주석과 코드가 다르면 코드를 규칙으로 쓰고 주석은 비고에 차이로 적는다. 주석에만 있고 코드가 강제하지 않는 것은 "주석만 있는 것"으로 뺀다.
- 조건문의 부등호 · 경계값(`>=` / `>`, `<> 'X'` 등)은 기억으로 쓰지 않고 인용 코드와 한 글자씩 대조한다.
- 반올림 · 자릿수 규칙은 계산식만 보고 쓰지 않는다. 변수 · 컬럼의 선언 타입(예: `DECIMAL(5,1)`)을 먼저 확인한다. 선언 타입이 이미 반올림하는 경우가 있다.
- `COUNT` 를 "인원"으로 옮기기 전에 세는 대상의 키를 확인한다. 키가 (학생, 과제)이면 인원이 아니라 행 수다.
- 조건이 **없는** 것도 규칙으로 적는다(예: 학급 필터 없이 전 단원 적용, 상태 조건 없이 전 행 갱신). 있는 조건만 찾다가 빠뜨린다.
- 선언만 되고 쓰이지 않는 변수를 "검증한다" · "비교한다"로 적지 않는다. 대입 뒤 실제로 비교에 쓰이는 줄을 찾는다.
- 파일에 없는 함수 · 테이블 이름을 쓰지 않는다. 문서의 이름은 `grep` 으로 1건 이상 나오는지 확인한다.
- 호출 방향을 거꾸로 쓰지 않는다. 호출 표의 "A → B" 는 A 의 몸통에서 B 를 부르는 줄을 근거로 단다.
- 검증 명령 · 표본 점검을 하지 않았으면 "했다"고 쓰지 않는다.
